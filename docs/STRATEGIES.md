# 内置投资策略与 Python 策略 API

本机版和 GitHub Pages 浏览器版使用同一份内置策略目录：[catalog.json](../src/investment_lab/strategies/catalog.json)。目录定义名称、说明、适用标的范围、参数类型、默认值、范围和填写提示；本机 `/api/strategies` 返回这份目录，Pages 构建也从该文件生成目录。修改内置程序时同步更新目录和策略测试。

内置程序依据决策日及此前已知的行情产生规则信号，不是对未来收益的预测模型。策略信号在当前日收盘后确定，订单由回测引擎按下一交易日模拟执行。依赖完整指标窗口的策略在预热不足或所需字段缺失时跳过信号，并在结果诊断中记录原因；不会用其他价格字段补足。自适应定投在回撤窗口不足时仍按基础金额定投；旧 `drawdown_buy` 保留非空的已有历史即可计算回撤的兼容行为，诊断会说明未满窗口；`rotation` 保留原完整窗口与默认月度轮动。所选成交价格模式、费用、交易规则和数据质量会影响结果；历史测试不代表未来表现或实际成交。

## 内置策略

每个策略的表单默认值与可填写范围以共享目录为准。网页的高级 JSON 字段可保留目录以外的旧参数；保存的配置同时记住各策略各自的参数。未完成的 JSON 原文也随草稿保留，只有在运行或应用为参数时要求有效对象，不会因输入尚未完成而静默改回旧参数。

| 分类 | 策略 ID | 用途 |
|---|---|---|
| 持有与定投 | `buy_hold` | 首次建立目标仓位后持有。 |
| 持有与定投 | `dca` | 按周、月、季或年首个策略决策日提交固定预算订单，下一交易日尝试成交。 |
| 持有与定投 | `adaptive_dca` | 定期定投；历史回撤达到阈值时按倍数增加当期投入。 |
| 组合配置 | `monthly_equal_weight` | 动态等权；低配优先补仓，按现有 5 个百分点阈值检查再平衡，可选指定检查日期或不再平衡。 |
| 组合配置 | `target_allocation` | 在周期首个决策日检查偏离阈值；空权重映射表示等权，非空映射未分配的比例留在现金中。 |
| 趋势与动量 | `moving_average` | 按当前价格相对简单均线的关系设置仓位。 |

| 趋势与动量 | `rotation` | 在多项所选标的中按过去动量定期轮动。 |
| 突破与回撤 | `donchian_breakout` | 按此前高低价通道突破入场、跌破退出。 |
| 突破与回撤 | `drawdown_buy` | 历史回撤达到阈值时建立目标仓位。 |

## 指标口径与调度规则

以下是项目当前实现的计算口径，不保证与其他交易软件的同名指标逐点相同：

- EMA：以每次选取的有限历史序列内第一个完整窗口的简单均值为种子，之后使用 `alpha = 2 / (window + 1)` 递推。每个决策日重新从有限窗口初始化；同次决策中的前后时点使用相同种子。这不是持续保存完整历史状态的 EMA，因此可能与其他软件逐点不同。
- RSI：对最近 `window` 个价格变化的正增量和负增量分别取简单平均，再计算 `100 - 100 / (1 + 平均涨幅 / 平均跌幅)`。这是简单平均 RSI，未使用 Wilder 平滑；全平为 50，仅有上涨为 100。
- ATR：每期真实波幅为 `max(high-low, abs(high-前收盘), abs(low-前收盘))`，最近窗口取简单平均，未使用 Wilder 平滑。ATR、唐奇安和随机指标需要明确的 OHLC 字段，不会由 VWAP 拼造 high/low。
- 布林带：窗口简单均值及总体标准差 `pstdev`；下轨为均值减标准差倍数。波动率目标和反波动率组合使用简单日收益总体标准差乘 `sqrt(252)` 年化，252 是研究假设。
- 使用历史单价的均线、动量、RSI、布林带及波动率策略遵循当前研究模式的默认字段：严格/估算 VWAP 使用 `vwap_value`，收盘/参考模式使用 `close`。改变指标字段不会自动改变成交价格模式。
- 周期策略在区间内对应周期的首个可用决策日检查；周按 ISO 周、季度按自然季度、年按自然年。每月自动入金在区间内月首交易日发生，与策略发信号、次日成交和投入预算是三个不同概念。反波动率组合在同周期历史不足时会等待并重试，不提前消耗该周期的调仓机会。

结果 `metadata.strategy_diagnostics` 记录预热不足、缺失字段等提示，并汇总到 `metadata.notes`；每轮最多保存 200 条去重诊断，超过时记录省略数量。没有产生订单不自动代表策略程序失败，需结合诊断和账户限制判断。

## Python 策略 API v2（本机版）

自定义 `.py` 文件放在本机数据目录的 `user_strategies` 文件夹，可使用网页编辑。保存会保留旧代码快照；提交回测时冻结 Python 源码、参数、引擎版本和数据快照。只运行自己信任的代码。本机 API 只监听回环地址，不应直接暴露至公网。GitHub Pages 只运行上表中的固定内置策略，不执行访客上传的任意 Python 代码。

```python
def initialize(ctx):
    ctx.state['entered'] = False

def on_session(ctx):
    symbol = ctx.symbols[0]
    prices = ctx.history(symbol, 20)  # 默认字段随价格研究模式；只含当前已知历史
    if len(prices) != 20 or any(value is None for value in prices):
        return
    average = sum(prices) / len(prices)
    ctx.order_target_weight(
        symbol,
        0.9 if prices[-1] > average else 0,
        '按已知价格相对均线设置仓位',
    )
```

- `ctx.date / symbols / params / state`：当日、所选标的、本轮参数、窗口内状态。
- `ctx.cash / debt / equity / positions / pending`：账户和待处理订单的当前副本。
- `ctx.history(symbol, count, field=None)`：Decimal 历史序列；未指定字段时使用成交模式对应字段。`field='close'` 可明确读取未复权收盘价。
- `ctx.bars(symbol, count)`：所请求的完整历史字段副本；缺失值保留为 `None`。
- `ctx.order_shares(symbol, quantity, reason)`：正数开多、负数卖出现有多头；期货数量为合约数。
- `ctx.order_value(symbol, amount, reason)`：按引擎可用价格换算下单数量。
- `ctx.order_target_weight(symbol, weight, reason)`：目标净值权重，可使用大于 1 的融资权重；实际成交受账户限制。
- `ctx.note(code, message, **details)`：可选的结果诊断接口，不下单、不改变策略时序。回溯支持 Engine7 或更早时，可先检查 `callable(getattr(ctx, "note", None))` 再调用。

`initialize` 在首个研究交易日的策略回调前运行，不能设置期初持仓。`on_finish(result)` 只得到结果副本，不再下单。滚动和留出研究会按窗口重新初始化策略并固定随机种子。每轮同一标的避免重复提交互相覆盖的目标订单。

策略只用 `history` / `bars` 返回的已知数据计算；不要从全量行情文件或未来日期取数。交易日历、公司行动、VWAP 和真实券商规则仍需按数据来源逐项核验。浏览器版与本机版的严格 VWAP、参考价格研究等数据口径边界相同。

CLI 请求例见 `config/example_run.json`。先从 `investment-lab list` 获取实际快照 ID；网页可直接选择数据快照。

## 版本与历史兼容

2026-10-05 的源码维护基线为 App0.2.5 / Engine8 / Strategy API2 / Schema1；这表示源码和格式基线，运行实例是否已加载以独立部署记录为准。现有 22 个策略 ID、请求结构和旧自定义策略接口保留。旧 `drawdown_buy` 的可用短历史行为与 `rotation` 的默认月度轮动保留；EMA 交叉修正、周期扩展与新增诊断可能使新运行结果不同，因此 Engine 版本递增。MACD 交叉条件改为显式比较当前两条线，数学上等价于原条件；不把它记作已证实的算法错误。历史运行必须使用其冻结的源码指纹、策略和依赖锁复现，不能拿新引擎直接替代。
